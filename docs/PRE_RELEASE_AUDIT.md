## 2. P1 — чего ждёт пользователь AI-агента и чего сейчас нет

**Управление чатами** (проверено):
- Переименование: есть `PATCH /sessions/{id}` и `api.renameSession`, но в UI только на вкладке Sessions, не в списке чата.
- Нет закрепления, цветовых меток, папок/групп, вкладок, архива, поиска по чатам. В модели `Session` нет полей `pinned`, `folder`, `color`, `archived` — нужна миграция Alembic.
- Правый клик по чату открывает стандартное меню WebView («Назад / Обновить / Сохранить как / Печать»), а не меню чата.

**Окно** (проверено):
- `decorations: true` зашито в `tauri.conf.json`; режима без рамок, своих кнопок свернуть/развернуть/закрыть, зоны перетаскивания и переключателя нет. В `capabilities/default.json` нет `allow-set-decorations`.
- «Focus mode» (Ctrl+\) только прячет список чатов и меню приложения, окно не меняет.
- Окно одно (`main`). Нескольких окон и разделённого экрана (несколько чатов рядом) нет.

**Экспорт** (проверено): есть экспорт одной сессии (`GET /sessions/{id}/export.md`, JSON на вкладке Sessions) и скрипт `backend/scripts/export_chats.py`. «Экспортировать всё» в интерфейсе нет.

**Уточнения (раунд 2)**: карточка вопросов берётся из ответа на отправку сообщения. После перезагрузки страницы или переключения чата она пропадает, остаётся текст в чате. Нужен эндпоинт, который отдаёт открытые вопросы задачи.

**Понятность интерфейса** (проверено по скриншотам): чипы `working`, `Agent`, `auto`, `fast · no check`, панель «Run setup», режимы Chat/Agent/Plan нигде не объяснены. Нет стартового экрана «что можно делать».

**Ошибки провайдеров** (проверено по логам): 402 `Insufficient Balance` (DeepSeek), 429/503 (Gemini), 404 для `gemini-2.5-flash`, ключи уходят в cooldown на ~18 часов. Не проверено, как это показано пользователю в интерфейсе; в логах видно, в UI нужно показывать «провайдер X недоступен, переключился на Y».

**Ресурсы** (проверено по логам): при 707–1465 МБ свободной RAM TaskRunner запускает 1 воркер. Параллельный EXECUTE (PR-5) на такой машине не даёт выигрыша. Нужна подсказка в UI.

**Безопасность агента** (не проверено в этой проверке): по умолчанию ли опасные шаги требуют подтверждения, видно ли пользователю, что агент собирается выполнить, где граница песочницы (`agent_sandbox_root`, `codex_sandbox_mode=workspace-write`). Аудит прав инструментов нужно провести отдельно.

**Приватность** (проверено): DLP чата выключен по умолчанию (`dlp_chat_enabled=False`) и не покрывает агентский цикл. Пользователю нужно сказать об этом в настройках простыми словами.

**Бюджет**: чип «≈ $0.00 today» есть; поведение при превышении лимита (`budget_gate`) не проверялось.

**Обновления и подпись** (не проверено): updater смотрит на GitHub Releases и имеет публичный ключ. Нужно проверить, что приватный ключ подписи сохранён в резервной копии и что установщик подписан (иначе Windows SmartScreen предупредит пользователя).

**Платформы**: проверено только на Windows 10 и тесты бэкенда на Linux. macOS и Linux-сборки не проверялись.

**Тесты фронтенда**: их нет. До 18.10 `npm run typecheck` ничего не проверял (solution-tsconfig с `files: []`), поэтому две ошибки раунда 2 (необъявленная `t`, карточка не подключена к режиму Agent) дошли до установленного приложения. Нужны vitest + jsdom и смоук-рендер ключевых страниц. Не проверено, вызывает ли `clean-machine-verify.yml` в CI `npm run typecheck`.

**Локализация**: строки карточек раунда 2 есть только в `en` и `ru`, остальные локали идут через fallback. Проверить, нет ли смеси языков.

**Документация**: `ARIA_FULL_TZ_v1.md`, `BOOST_PLAN.md`, `REVIEW_WAVE0_1.md`, `ANCHOR.md`, `WORK_NOTES.md` — внутренние рабочие файлы. Решить, что публиковать, и написать короткий `README` для пользователя (установка, ключи, первый запуск, режимы, где лежат данные, как сделать резервную копию).

## 6. Ручной сценарий раунда 2

1. Новый чат, режим **Agent**, расплывчатая задача («сделай отчёт»).
2. Появляется карточка уточнений с вопросами; красной строки «already queued» нет.
3. Ответить на один вопрос — цель задачи не меняется, остальные остаются.
4. Нажать «Принять допущения» — оставшиеся вопросы уходят в допущения.
5. Появляется план с подтверждением (шаги, зависимости, критерии).
6. Выполнение, затем отчёт аудита.
7. `GET /tasks/<несуществующий id>/audit-reports` отвечает 404.

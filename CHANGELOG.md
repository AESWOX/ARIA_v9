# Changelog

## 0.2.1

- **Исправлено: Agent и Plan не видели ключ из мастера первого запуска.** Ключи, сохранённые в мастере или на странице Keys, теперь доходят до исполнителя задач и до фонового планировщика без перезапуска.
- **Исправлено: шаги плана не получали результаты предыдущих шагов.** Шаг видит запрос, контракт задачи, последние сообщения диалога и результаты шагов из `depends_on`; чтение несуществующего файла стало ошибкой шага.
- **Работа с одним ключом.** Сжатие контекста и подсказки больше не требуют ключа Gemini; зрение (`vision_analyze`) работает через DeepSeek Flash, если есть только ключ DeepSeek.
- **Логи.** Сбой задачи виден в чате с причиной и замечаниями аудитора; на странице Logs кнопка очистки, вкладки по компонентам, строки на каждый вызов инструмента, смену статуса задачи и вердикт аудита. Токены и ключи маскируются в `backend.log`.
- **Безопасность.** `vision_analyze` читает изображения только внутри песочницы и не блокирует цикл событий. Обновлены `fastapi`, `starlette`, `python-multipart` и npm-зависимости (`pip-audit` и `npm audit` без находок).
- Версия бэкенда в API приведена к версии приложения.
- **Исправлено: «0.0.0 (dev)» в установленной сборке.** Self-test, `/system/stats` и `/aria/update/check` брали версию из метаданных пакета, которых нет в упакованном `backend.exe`. Версия теперь одна константа `aria.version.APP_VERSION`, тест сверяет её с Tauri, Cargo и npm.
- **uv ставится вместе с приложением.** Установщик (NSIS) отдельной фазой скачивает uv 0.13.5 с GitHub Releases, проверяет SHA-256 и кладёт в `<папка приложения>\uv`; MCP `fetch` (uvx) работает на чистой машине. Нет сети — установка продолжается, uv можно поставить позже. Бэкенд ищет uv сначала рядом с приложением, потом в PATH.
- **Мастер первого запуска.** Подписи кнопок на шагах с ключом и моделью больше не накладываются друг на друга: кнопки не сжимаются и не переносят текст, нижняя строка переносится целиком.
- **Уточняющие вопросы.** Приветствия, благодарности и «ок» («hi.», «привет, как дела?») больше не вызывают пять вопросов; любая просьба по-прежнему проходит через уточнение. Язык вопросов, вариантов и сообщения следует за языком запроса (русский, украинский, английский).
- **Карточка уточнений переживает перезагрузку.** Открытые вопросы приходят вместе с состоянием запуска (`GET /sessions/{id}/run`), окно после перезагрузки загружает состояние запуска первой сессии и показывает карточку снова; опрос идущей задачи тоже возобновляется.
- **Исследование кода.** Новый инструмент `file_grep`: поиск текста или regex по содержимому файлов, ответ `путь:строка: фрагмент`; `.git`, `build`, `node_modules` и бинарные файлы пропускаются. `file_read` читает диапазон строк (`start_line`/`end_line`) с номерами строк и сообщает об обрезке; `file_search` пропускает служебные папки и возвращает стабильно отсортированный список. Папка проекта (`agent_project_root`) доступна агенту только для чтения (`scope="project"`): запись и команды работают только в песочнице.
- **Clean test data** показывает, что будет удалено, спрашивает подтверждение и делает копию базы перед удалением. Ожидание блокировки SQLite увеличено до 10 с.
- **Навигация из пяти пунктов.** В боковой панели остались Chat, Sessions, Files, Logs и Settings; остальные страницы (модели, навыки, заметки, cron, аналитика, ключи, конфиг, профили, MCP, вебхуки, каналы, pairing, система, документация) открываются из хаба Settings. Страница «Плагины» больше нигде не показывается.
- **Logs.** Кнопки «Open logs folder» и «Export diagnostics» (архив без ключей и токенов); в заголовке показывается реальное имя файла (`backend.log`), а не `agent.log`.
- **Обновление окна.** F5 и переход по ссылке на путях страниц (`/sessions`, `/logs`, `/config` и др.) открывают приложение, а не отдают JSON 401.
- **Нерабочие кнопки скрыты.** Действия на заглушках 501 (pairing, channels, OAuth-вход и отключение, config-migrate, куратор, пул учётных данных, debug-share, «Плагины») убраны из интерфейса.
- **Поиск хранилищ Obsidian ускорен.** `/vault/discover` больше не блокирует сервер: подсчёт заметок ограничен 5000 файлами и бюджетом времени, ответ кэшируется на минуту; флаг `note_count_capped` показывает, что счёт урезан.
- **Контекст и стоимость в шапке чата.** Шапка показывает занятость контекста (`ctx N%`) и стоимость текущего чата по usage провайдера и ценам модели; если цен нет, стоимость честно не показывается. `GET /chat/sessions/{id}/usage` отдаёт окно модели, токены, `session_cost`, `priced`, `priced_messages`/`unpriced_messages`.
- **Stop и Cancel — разные кнопки.** Stop в Chat обрывает ответ (сообщение не сохраняется, можно писать снова), Cancel в Agent/Plan завершает задачу.
- **Живая панель плана и чистый New chat.** Пока задача идёт, план обновляется каждые 2 с, вместо «none yet» показывается «planning…». New chat очищает карточку уточнений и состояние прошлой задачи и возвращает вкладку Chat.
- **Параллельные субагенты.** Не более 3 одновременно; при свободной RAM меньше 1500 МБ — 1. Причина снижения и флаг `swarm_enabled` видны в `GET /tasks/runner/status`.
- **План: аргументы инструментов и зависимости.** Шаги плана получают аргументы инструментов (`input`/корневые поля), а шаги с упавшей зависимостью помечаются `skipped` и не вызывают модель.
- **Расписание задач проверяется.** Cron-выражение валидируется тем же парсером, что и планировщик: мусор отклоняется с ответом 422, а не сохраняется молча.
- **Тесты.** Поведенческие тесты для роутеров system, tasks, cron, sessions, config, skills и profiles.
- **Скорость ответа.** Провайдер больше не держит чат минутами: одна попытка на провайдера, быстрый переход к следующему, короткие таймауты и предохранитель после серии отказов; стрим переключается на следующую модель до первого токена, а не после 20-секундного ожидания. Чат по умолчанию отвечает через DeepSeek (быстрый первый токен), бесплатные модели остаются запасным путём. Цель — первый токен p95 ≤ 12 с.
- **Telegram без привязки.** На вопрос о личных сообщениях или своём аккаунте агент не отвечает из памяти, а показывает карточку «Telegram не подключён» с переходом в Channels. Публичные каналы (`t.me/s`) работают как раньше. Теперь там же можно подключить бота: инструкция от @BotFather, поле токена и поле канала через @ — токен сохраняется локально, гейт снимается.
- **Память не тормозит чат.** Автопоиск по заметкам Obsidian ограничен 1.5 с на ответ и кэшируется на 2 минуты; раньше большой vault задерживал `chat_prepare` на 5–15 с.
- **Честная память.** На «мы такое делали?» при пустой памяти и заметках агент прямо говорит, что не нашёл, и не отрицает прошлую работу.
- **Чат и навигация.** Gateway и Active Sessions в боковой панели стали отдельными ссылками; в поле ввода появилась кнопка «+» для выбора файлов; чат занимает всю высоту окна; пустые значения в селекторах больше не показываются как «None».
- **Composer как в OpenCode.** Плавающая карточка снизу: `+` для файлов, выбор модели и глубины мышления, `Chat | Plan`, `Advanced`, Send/Stop; textarea растёт до 6 строк, Enter отправляет, Shift+Enter переносит строку; drag&drop и вставка файлов работают.
- **Вкладки сессий.** Слева больше нет постоянного списка: открытые чаты — вкладки сверху, с индикаторами «working / needs you / new», переименованием, закрытием и `+`. Открытые вкладки и активная сохраняются между запусками; новый чат не создаёт запись в БД до первого сообщения.
- **Advanced без сюрпризов.** Сохранение профиля больше не меняет профиль новых чатов молча: для этого есть явная кнопка «Use for new chats». Boss + helpers доступны только в Plan, Reviewer появляется только при строгой проверке, есть Reset.
- **Темы Black / White / Gray.** Новый профиль стартует с Black; White и Gray доступны рядом. Остальные темы и Hermes остаются опциональными.
- **Правая рабочая панель.** Вместо одного экрана информации — вкладки Plan / Files / Info: план и Approve, вопросы уточнения и аудит, затронутые файлы и вложения, кнопки «Open Files» и «Open logs folder»; Info остаётся для контекста и стоимости.
- **Чат стал удобнее.** Слева вернулся список сессий (на широком экране) вместе с вкладками; чат занимает всю высоту и не сжимается при росте переписки; поле ввода начинается с одной строки и растёт по мере набора.
- **Уточнения — в чате.** Карточка вопросов открывается прямо в ленте, как в OpenCode; на неё можно ответить и кнопками, и обычным текстом в composer — блокировка ввода на `awaiting_clarification` снята.
- **Инструменты в Plan.** Задачи в режиме Plan по умолчанию идут в роль `coder` (write/shell с Approve), а не в read-only `general`; Boss + helpers по-прежнему через `orchestrator`.
- **Hermes — опционально.** Фоновая фигура Hermes выключена по умолчанию, тема Hermes и старые темы убраны в раздел Optional; Black теперь действительно чёрный и выставляется для старых сохранённых тем один раз.
- **Окно на половину экрана.** Кнопки «Snap left / Snap right», двойной клик по заголовку — maximize/restore, Win+Left/Right и перетаскивание к краю работают: минимальная ширина окна снижена до 760 px, чтобы половина экрана помещалась и при 125 % масштабе.
- **Проверки перед заморозкой 0.2.1.** Поведенческими тестами закрыты: Telegram-гейт и подключение бота (валидация токена и канала, токен не возвращается в ответе), ограничение и кэш автопоиска по vault, таймауты и предохранитель провайдеров, DeepSeek-first с явным переключением на free, честная память на русском и английском, правило 0 уточнителя и язык карточек, независимые профили сессий, роль `coder` в MCP, сохранение `ui_prefs` на диск, Stop/Cancel в пределах бюджета.

## 0.2.0: первый публичный релиз

Что входит в релиз (подробный обзор и ограничения: [docs/PROJECT_STATUS.md](docs/PROJECT_STATUS.md)).

- **Агент.** Три режима: Chat (без инструментов), Agent (цикл с инструментами и подтверждениями), Plan (уточняющие вопросы, формализованное ТЗ, план-граф, параллельное исполнение, аудит по критериям приёмки). Команда агентов: оркестратор и роли с делегированием.
- **Инструменты.** Около двух десятков: файлы, оболочка (default-deny и песочница), веб-поиск и загрузка страниц с защитой от SSRF, Obsidian-совместимые заметки, память (SQLite FTS5), навыки, зрение.
- **Провайдеры.** OpenAI-совместимые API (Gemini, Groq, DeepSeek и др.), пулы ключей, автоподбор цепочек моделей, переход на запасные модели при 5xx, 429, 402, 403, 404 и пустом ответе, бюджетный шлюз, сжатие контекста.
- **MCP и плагины.** MCP-клиент (stdio и streamable HTTP, OAuth 2.1, default-deny, Approve для пишущих инструментов), встроенный каталог, импорт Agent Plugins с отключёнными серверами.
- **Хуки и чекпоинты.** События `pre_tool`, `post_tool` и др., снимок файла перед записью с откатом из интерфейса.
- **Безопасность.** Токен на всех маршрутах API и на WebSocket, проверка заголовка Host, окружение оболочки по allowlist, поиск файлов не выходит за корень песочницы, шифрование данных DLP на диске с проверкой целостности (encrypt-then-MAC).
- **Приложение.** Tauri + React, 16 языков интерфейса, темы, экран первого запуска, расписание задач (cron), профили, экспорт сессий, резервные копии.
- **Сборка и проверки.** Воспроизводимая сборка установщика (PyInstaller + Tauri NSIS), оркестратор `rebuild_and_smoke.py`, 1433 теста бэкенда, сканер секретов в релизной сборке.
